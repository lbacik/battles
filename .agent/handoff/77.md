### Domain (`domain/scenario.js`)

New pure helpers in an `--- Unit add, edit, duplicate, and delete ---` section placed
just before the `--- Undo history ---` section (the undo header was preserved). All
clone the input, throw `Error` on refusal, and run `refuseConflictingUnitEdit`
(`validateScenario` errors naming `units[index]` → throw first), mirroring the tracer's
`refuseIfConflicting`. No catalogue import (module policy: catalogue membership is
playability, not structural — callers pass preset metres in; scenario stores metres):

- `unitDerived(unit)` → `{ ranks, frontageM, depthM } | null` via `unitFootprint`
  (inspector and map share it, so numbers always match the true-scale rectangle).
- `createUnit(document, { sideId, troopType='hoplite', soldiers=100, files=10,
  lateralInterval=1.8, rankDepth=1.8, facing?, name?, searchRect=null })`
  → `{ document, unitId }`. Side defaults to first side; facing via
  `defaultFacingForSide`; name via `suggestUnitName`; throws
  `No free space in the current view: pan or zoom out, then add the Unit again.` when
  `findFreeUnitPosition` returns null.
- `duplicateUnit(document, unitId, searchRect=null)` → `{ document, unitId }`;
  name `${source.name} copy` uniquified; same-size footprint; throws `... then
  duplicate the Unit again.` when full. Throws `Unit not found.` for unknown id.
- `deleteUnit(document, unitId)` → document; throws `Unit not found.`.
- `updateUnitName` (required + unique case-insensitive, tracer messages),
  `updateUnitSide` (must exist, `Side is required.`),
  `updateUnitTroopType(document, id, troopType, preset=null)` (required; when `preset`
  `{lateralInterval, rankDepth}` is passed both spacings are pre-filled in the same
  step — the editor passes the new type's normal preset),
  `updateUnitNumbers` (integers ≥1, files ≤ soldiers, tracer messages),
  `updateUnitSpacing` (finite >0, ≤ `MAX_SPACING_M`, rounds to 0.1 m via `round1`).
